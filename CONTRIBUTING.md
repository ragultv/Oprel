# Contributing to Oprel SDK

First off, thank you for considering contributing to Oprel SDK! We value community input and feedback.

Because of these restrictions, contributing code requires you to agree that any changes you submit (via Pull Requests) become part of the main project and are subject to the same license restrictions by the repository owner.

## How Can You Contribute?

### 1. Reporting Bugs
If you find a bug, please open an issue on GitHub. Include:
- A clear and descriptive title.
- Steps to reproduce the issue.
- The version of Oprel SDK you are using.
- Your operating system and environment details.

### 2. Suggesting Enhancements
We are always looking for ways to improve Oprel SDK. If you have an idea:
- Open an issue detailing your feature request.
- Explain why this enhancement would be useful to most users.

### 3. Submitting Pull Requests
If you'd like to submit a fix or a new feature:
1. Fork the repository.
2. Create a new branch for your feature (`git checkout -b feature/amazing-feature`).
3. Commit your changes (`git commit -m 'Add amazing feature'`).
4. Push to the branch (`git push origin feature/amazing-feature`).
5. Open a Pull Request against the `dev` branch of this repository.

By submitting a Pull Request, you agree to license your contribution under the project's existing license terms and assign the necessary rights to the repository owner to distribute your contribution.

## Code of Conduct
We expect all community members to interact professionally and respectfully. Harassment or abusive behavior will not be tolerated.
